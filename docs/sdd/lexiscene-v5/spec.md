## 0. 现有产品上下文(审计基线)

LexiScene(词境阅读)是一个"把用户背过的词放进真实语境"的英语阅读巩固工具。当前实现(分支 `codex/v2-mvp-foundation`,已推送 origin):

- **前端**: Vite + React 18 + TS + Tailwind + Zustand + Dexie(IndexedDB),9 个页面(Home/Library/Reading/History/Favorites/Admin/Auth 系)
- **后端**: Cloudflare Worker + Hono + D1(13 张表,7 个迁移),Resend 邮件,Turnstile 人机验证,Cron 每日文章轮换
- **已交付代际**: V1(无账号本地版)→ V2(MVP 基线)→ V3(账号/邮箱验证/云同步/词典/内容池/收藏)→ V4(PDF/OCR 导入、英文题+翻译+证据、双质量通道)
- **数据链路**: 本地优先(Dexie)↔ D1 双向同步(`/api/sync/*`),AI 生成文章走 DeepSeek/千问/豆包 三路 + 确定性质量校验 + 一次修复重试
- **内容池**: 脚本批量生成候选 → AI 预审 → 管理员人工审核 → Cron 按难度轮换发布

## 2. 战略立项

- **核心赌注**: 小圈子学习工具的死穴不是缺功能,而是**信任崩塌**——一次白屏、一次"昨天还能用今天坏了"、一次忘了密码要找人,足以让朋友弃用。把地基打牢 + 让进步可见,词汇巩固闭环才转得起来。
- **最窄切入**: 不加新平台、不换架构、不碰商业化。三个功能(测验/看板/忘记密码)+ 四条加固线 + 一次上线,全部在现有 Vite+React+Worker 栈内完成。
- **护城河(自用尺度)**: 数据所有权(词表和进度在自己手里,云端可同步)+ 全闭环(读→查→测→看得见进步)是同类单点工具没有的;不追求商业护城河。
- **为什么现在**: V4 刚交付英文题与质量管线,功能面上了一个台阶,但生产环境还停在旧版、测试为零——此时继续堆功能,回归风险只会指数上涨。
- **kill-criteria(放弃阈值)**: 上线后连续 4 周,包括自己在内**无人每周完成 ≥3 篇阅读** → 停止投入新功能,降级为"仅维护"。
- **写码前最便宜的证伪动作**: 无需新证伪——看板本身就是测量仪器。上线后用看板真实数据(自己 + 2 个朋友)两周即可验证 kill-criteria 的分母是否成立。
- **最脆假设**: "朋友会主动回访"(我背单词的意愿 ≠ 朋友的意愿)。证伪动作与 kill-criteria 共用:看板直接暴露回访数据,不需要额外埋点。

## 3. 产品形态与分发

**形态: Web App(私有部署,非 website)。** 用户通过固定 URL 访问,不面向搜索引擎获客。

- **SEO/GEO: 显式不适用。** 理由:使用范围 = 自己和朋友,无获客需求;生产域名不做可索引优化,`robots` 保持默认。此项为显式决策,非遗漏。
- **Onboarding(首屏拿价值的秒数)**: 已注册用户登录后首屏 = Dashboard,首屏文案现状:

```
词境阅读 · LexiScene
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│📚 词库    │ │✨ 今日文章│ │📊 学习看板│ │🎯 词汇测验│
│ 812 词    │ │ 已就绪    │ │ 本周 3 篇 │ │ 10 词/轮 │
│[管理]     │ │[开始阅读] │ │[查看]    │ │[开始测验] │
└──────────┘ └──────────┘ └──────────┘ └──────────┘
```

  新用户注册后首次进入的空态文案(真实文案,实现时照抄):
  - 词库卡:"词库还是空的 — 导入你背过的词,第一篇文章会用它们写出来。"
  - 看板卡:"还没有阅读记录 — 读完第一篇,这里会出现你的第一条曲线。"
- **留存/复访**: 靠 Cron 每日文章轮换(已有)+ 新增的每日测验入口(见 §5)。**通知策略: 不做推送**(自用档位,推送的运维成本 > 收益);复访信号 = 首页"今日文章已就绪"状态卡,等价文案:"ⓘ 今日文章已就绪(雅思)· 你的词库有 812 词"。
- **分发**: 不分发。朋友通过私人 URL + 邮箱注册(Turnstile 已挡机器人)。

## 4. 品牌与产品体系

### 4.1 定位陈述

> For **备考 CET-4/6、考研、雅思、托福,背了几千词却在真实阅读里认不出的中国学生**, LexiScene(词境阅读) is the **词汇巩固阅读工具** that **用你自己的词表生成并挑选真实语境文章,让背过的词在阅读里反复出现,再用测验把它们钉进记忆**. Unlike **百词斩/不背单词的机械重复刷词**, it **每篇文章都由你的词表驱动,并强制词汇复现与题目证据**。

### 4.2 命名方向

现有命名 **LexiScene / 词境阅读**(隐喻型:Lexi(词)+ Scene(语境/场景),中文"词境"直译同构)。审计发现 Prd.md 里的"词遇读"为弃用旧名。**本版裁决: 统一使用 LexiScene / 词境阅读**,所有文档与 UI 落地一致(归入 AC-014 文档收敛)。风险备注:lexiscene 相关域名是否被占未核实,自用档位不影响。

### 4.3 品牌声音(Voice & Tone)

三条原则:① 鼓励不施压——学习工具不制造焦虑;② 说人话——错误提示永远带"下一步怎么办";③ 界面中文、语料英文——英文内容原样呈现,不夹翻译腔。

同一句话的腔调对比(硬证据):

- 通用腔:`导入成功。词表已保存。`
- 品牌腔:`词库收好了 — 98 个词,其中 12 个会出现在今天的文章里。`
- 通用腔(测验答错):`回答错误。`
- 品牌腔:`差一点 — 正确拼写是 analyze。这个词会再回来找你一次。`

### 4.4 产品体系(系统主线)

主线 = **"让背过的词在真实语境里活下来"**:

导入词库(材料进仓)→ 读今日/生成文章(词在语境复现)→ 划词查词典(即时理解)→ 做阅读题(理解检验)→ **词汇测验(主动提取,新增)** → **学习看板(复利可见,新增)**。

两个新功能不是孤立卡片:测验是"读后主动提取"环节,把巩固从"被动读"延长到"主动回忆";看板是整条主线的仪表盘,回答用户唯一关心的问题——"我背的词真的活下来了吗?"(词汇复现率曲线直接可视化 BR-04 的词频约束成果)。忘记密码则是这条主线对"人"的兜底:账号进得来,闭环才转得动。

### 5.2 新增页面

**`/quiz` 词汇测验页**(两模式)
- 功能: 从**当前激活词库**(与阅读生成/高亮同源的词库)抽 10 词出题;模式一"看词选义"(1 个词 + 4 个中文释义选项,1 正 3 干扰,干扰项取自其他词的释义);模式二"见义拼词"(显示中文释义 + 首字母与字母数提示,键盘输入);每题即时反馈;答错的词自动排到当轮队尾重练一次;结束显示本轮正确率与错词数。
- 状态:
  - 空: 词库 < 10 词,或可出题词(有释义)不足 4 个 → "词库里的词还不够一轮 — 至少导入 10 个词再开始。"(词库为 0 时按钮置灰 + 引导去 /library/import)
  - 加载: 抽词与释义拉取期间显示 Spinner(词典走 /api/dictionary/batch,命中本地缓存则瞬时)
  - 成功: 出题 10 词;若部分词无释义,文案:"已用 8 个词出题 — 2 个词暂无释义,已跳过。"
  - 失败: 词典接口不可达且无缓存 → "词典服务暂时不可用,稍后再试。"[重试]
  - 无权限: 未登录 → 跳 /login(与站内现有守卫一致)
  - 重复提交: 提交答案后按钮锁定至判定返回,防连点双计
- 示例(模式二题面,真实词库词):

```
v. 模式;图案;花样          ← 词库词: pattern
p _ _ _ _ _ _              ← 首字母 + 7 个字母
[ 输入框 ]                  ← 输入 "Pattern" → 判对(大小写不敏感)
                            ← 输入 "patterns" → 判错,展示正确拼写 pattern
```

- 对应 AC: AC-002(选义)、AC-003(拼词)、AC-004(记录与看板联动)

**`/stats` 学习看板页**
- 功能: 三张指标卡,支持"近 7 天 / 近 30 天"切换。指标口径(实现与验收同口径):
  1. **每日阅读量**: 按北京时间日历日统计"完成阅读"篇数(reading_progress.completedAt)
  2. **词汇复现率**: 时间窗内读过文章的 `vocabHitIds` 并集去重词数 ÷ 当前词库总词数 × 100%
  3. **得分趋势**: 阅读得分(score/5)与测验正确率两条序列,按日聚合折线
- 状态:
  - 空: "还没有阅读记录 — 读完第一篇,这里会出现你的第一条曲线。"(词库有词时给 [开始阅读] 按钮)
  - 加载: Skeleton 骨架(用现成组件,不得白板)
  - 成功: 三卡 + 折线;示例渲染 [ILLUSTRATIVE-EXAMPLE: 每日阅读量 近7天 = 2,3,0,1,1,0,2 · 复现率 61%→74% · 得分趋势 阅读均值 76% / 测验均值 80% | 待上线后以真实数据替换]
  - 失败: 本地数据读取异常 → "数据加载失败 — 你的数据都在,重试即可。"[重试]
  - 无权限: 未登录跳转;无付费态(本产品无付费)
  - 重复提交: 不适用(纯读)
- 对应 AC: AC-005

**`/forgot-password` + `/reset-password` 忘记密码**(两步式)
- 功能: 输入邮箱 → 收 6 位验证码(复用现有邮箱验证码模式:哈希存储、有效期 10 分钟、60 秒重发间隔)→ 输入验证码 + 新密码 → 重置成功后**该账号所有已登录会话失效**,跳登录页。
- 状态:
  - 成功: 统一文案"如果该邮箱已注册,验证码已发送 — 请查收(包括垃圾邮件)。"(**无论邮箱是否存在都返回此文案,防枚举**)
  - 加载: 发送按钮 Spinner + 60 秒倒计时禁用
  - 失败: 验证码错误 → "验证码不对或已过期,重新输入或 [重新发送]";连续 5 次错误 → 本验证码作废,需重新发送
  - 无权限: 已登录用户访问 → 提示"你已登录 — 如需改密请先退出"并跳转
  - 重复提交: 发送按钮倒计时即防重复;重置提交后按钮锁定
- 对应 AC: AC-006

| 功能 | 靠什么实现 | 现成轮子 | 难度量级 |
|---|---|---|---|
| 词汇测验(两模式) | 纯前端页面;词库数据与词典释义接口(/api/dictionary/batch + 本地缓存)均已存在;判定是字符串归一化比较 | 无需新轮子;释义数据源已内置 | 低(小白能做级;唯一要点是判分边界与干扰项生成) |

| 忘记密码 | 复用现有邮箱验证码模式(哈希存储/有效期/重发间隔)与 Resend;Worker 加两个端点 | Resend 已接入;验证码模式现成 | 低 |
| 测试基建 | 单测框架引入(选型归 tech-spec);LLM 调用点需可注入假响应 | 测试框架与断言库全是现成轮子 | 单测低;E2E 冒烟中等(需 mock LLM 与本地 D1 摊子) |
| ErrorBoundary/空态组件 | React 类组件边界 + 已写好的三个 UI 组件接入 | React 内建 + 组件已在库内 | 低 |
| KV 限流启用 | 配置解注释 + 核对 KV 计数路径 | Cloudflare KV 原生 | 低(要点是部署后真实验证,已写进 AC-009) |
| daily 双路径收敛 | 删分支 + 依赖 AC-010 迁移完成 | — | 低(风险在顺序:先迁移后删) |
| Worker 拆分 | Hono 路由分文件,机械移动 | Hono 原生路由组织 | 中(风险=回归,靠 AC-001/AC-017 兜底;先测试后拆,顺序不可反) |
| 类型单源 | 以 Zod schema 推导前端类型,删手抄定义 | zod 类型推导现成 | 中(要点是构建引用路径,归 tech-spec) |

| 文档收敛/死代码清理 | 纯移动与删除 | — | 低 |

**结论: 无任何功能超出"有现成轮子 + 低-中难度"区间,全部可做。** 唯二需要纪律的是拆分顺序(先测试后重构)与发布顺序(先备份后迁移),均已写为 AC 约束。
